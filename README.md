# Кибердвор

Платформа любительских киберспорт-турниров по Dota 2, CS2 и FPV Kamikaze Drone. Организатор запускает турнир за 5 минут. Игроки без команды попадают в составы через драфт: капитаны выбирают их по анкетам. Рейтинг считается по Glicko-2 отдельно для каждой игры.

Матчи идут на ПК самих игроков или на нейтральном ПК. Платформа хостит только сайт: фронтенд, API и базу данных. Вход только через Яндекс ID с обязательной привязкой Steam: один человек — один аккаунт.

> Проект в разработке (учебная практика, кейс 46). Часть модулей API ещё не подключена к приложению.

## Структура

```
apps/
  api/        Fastify + Drizzle + PostgreSQL: REST, WebSocket, вся серверная логика
  web/        сайт на React + Vite
  desktop/    десктоп-клиент на Electron: матчи, выбор хоста, сервер CS2 на ПК игрока
packages/
  shared/     типы, zod-схемы, константы, интерфейс античита
  ui/         общие React-компоненты сайта и клиента
  config/     общие настройки TypeScript, ESLint, Prettier
  private/    закрытая часть (сабмодуль, нужен доступ к приватному репозиторию)
```

## Клонирование

С доступом к закрытой части:

```sh
git clone --recurse-submodules git@github.com:noki28200-coder/Kiberdvor.git
```

Если репозиторий уже склонирован без сабмодуля:

```sh
git submodule update --init packages/private
```

Без доступа к закрытой части клонируйте как обычно:

```sh
git clone https://github.com/noki28200-coder/Kiberdvor.git
```

Если клонировать с `--recurse-submodules` без доступа, git покажет ошибку для `packages/private`. Основной репозиторий при этом склонируется полностью, и с ним можно работать.

## Запуск

Нужны Node.js 22+, pnpm 12 и Docker.

```sh
pnpm install
docker compose up -d                  # PostgreSQL для разработки
cp .env.example apps/api/.env         # заполните нужные переменные
pnpm --filter api db:migrate          # схема базы данных
pnpm dev                              # API (порт 3100) и сайт (http://localhost:5173)
pnpm --filter desktop dev             # десктоп-клиент
```

Чтобы войти без ключей Яндекс ID, укажите в `apps/api/.env` `DEV_AUTH=true`. Это тестовый вход только для разработки, в production он запрещён.

Проверки перед коммитом:

```sh
pnpm lint && pnpm typecheck && pnpm test
```

### Без доступа к закрытой части

Всё собирается и запускается без `packages/private`. Вместо античита работает заглушка из `packages/shared/src/anticheat.ts`. Клиент тогда показывает «Публичная сборка без античита», а сервер помечает отчёты как `unchecked`. Остальные функции работают одинаково.

## Закрытая часть

В приватном репозитории живут античит и проверки целостности клиента. Публичный код знает только интерфейсы `ClientAntiCheat` и `ServerAntiCheat` из `packages/shared`. Реализация подключается, только если `packages/private` скачан:

- `packages/private/src/client.ts` экспортирует `clientAntiCheat`. Десктоп-клиент подставляет его при сборке, см. `apps/desktop/build.mjs`.
- `packages/private/src/server.ts` экспортирует `serverAntiCheat`. API загружает его при запуске, см. `apps/api/src/anticheat.ts`.

Античит в клиенте — только дополнительный барьер, потому что Electron-приложение легко распаковать. Результаты матчей, рейтинг и подписку решает только сервер (`apps/api`). Вердикт античита лишь помечает матч для проверки организатором.

## Секреты

Ключи (Яндекс ID, Steam, ЮKassa, Telegram) задаются только через переменные окружения. В репозиторий попадает лишь `.env.example` с пустыми значениями, файлы `.env` в git не добавляются.
